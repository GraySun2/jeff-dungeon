# Contributor guidance

For any chat or person changing this scaffold, or using it in a game repo. Read [README.md](README.md), [PROJECT_STATUS.md](PROJECT_STATUS.md) and [FRAMEWORK_METHOD.md](FRAMEWORK_METHOD.md) before a substantial change.

- Keep the difference between the reusable scaffold, the worked example (a fixture), a prototype and a game.
- Keep source facts, interpretation, proposals, desk checks and player observations apart, and label which is which.
- Everything here is PROPOSED or OPEN. Only the adopting owner's own words lock a choice; quote them.
- Keep audience, setting, tone, camera, engine, art, platform, player count and business model open until the adopting owner decides.
- Barony and the other reference games are references, not templates. Don't copy their names, settings, classes, items, numbers or art. The example's numbers are fixtures.
- Don't mark a gate passed because a document, trace or script exists. Record the method, the counts, the limits and the owner's decision.
- One owning document per rule. If two disagree, settle the owner and fix the other.
- Co-op players are Multiplayer Adaptation's ([PACKAGE.md](https://github.com/bigfootcdl/nat-pod/blob/main/scaffold/packages/multiplayer-adaptation/PACKAGE.md)). Write requirements for it; don't duplicate it here.
- Research lives once in the research library (D-012). Point to it from [research/SOURCES.md](research/SOURCES.md); don't copy it in.
- Add navigation for any new file, and end each file with the footer below.
- Report what changed, which checks you actually ran, and what is still uncertain.

The user's instructions take precedence over this guidance.
